## 0. 冻结决定与边界

1. 玩家是 Producer，不是逐日排班员。**页面是信息空间，会议是决策空间**；日常训练、已批准的日程、普通 Live、Cheki、结算默认由 Staff 依策略执行。玩家可 Attend 或 Delegate。
2. 游戏日按 **JST** 推进；日推进可连续运行最多七天或至下个重要节点，遇必须人工处理的 blocking decision 才中断。Live Report 与普通 Weekly Review 不阻塞。
3. 序章强制经历：2013-01 创始/15人面试、两首原创固定制作、**2013-05-24 赤坂 BLITZ 出道**、2014-01/02 试验性定期、**2014-03-05 起每周三正式定期**、莉奈毕业、2014-07 下旬 1st One-man、**2014-08-02 TIF**。公司保证机会，不保证票房、满意度、粉丝或财务结果。
4. 3–7 人小团、8–10 人中团、11–18 人大团。**小团和中团常规 Live 全员出演、全员参加获准特典会；9人团绝不设常规选拔轮换**。只有大团常规采用选拔/轮换。明确的合同限员、个别成员受邀或衍生单位活动按合同处理，不把例外变成中团常态。
5. 2013-10 只有**小团路线（3–7人）**触发公司支持的第二次甄选／补员剧情，使用全新候选池；8–10 人中团和 11–18 人大团不自动补员。以当日 active 正式签约人数为准；不可悄悄复活被拒候选人。历史剧情中的莉奈毕业仍发生，动机/交接可受经营影响。
6. 2013–14 的免费商场 Live **收入为零**；学校/企业封闭活动有合同出演费、默认无收费特典会，不作为公开拼盘曝光；普通售票拼盘按本文件分账。**封闭活动在目前经济回归测试中排除**，但类型保留供玩家可选剧情。
7. Cheki **逐成员、逐场、逐价格档**统计。至少有 **¥1,000、¥2,000** 两档，默认成员分成是**销售总额的20%**。不要再按全团 Cheki 统一分摊或假设全为 ¥1,000。
8. 粉丝采用 **Fan Market v0.2 的团队 P/O + 成员 A_i/W_i**：Performance/有效曝光主要影响获客；成员特典会交流和持续互动主要影响 affinity 留存、消费强度。**旧 persistent Core、C_i 和独立 BoxRate 已废弃**。不新造“成员创收”属性或硬编码 5/9/15 人收入乘数。
9. 旧模拟表是敏感性实验，**不是 Runtime 真值**；¥210/张其他成本、¥2,000 档占比30%、成员正边际贡献都是校准假设，不得伪装为历史事实或给销量保底。

## 1. 玩家流程、页面与自动化

### 1.1 页面

- **Inbox**：Blocking → 待办/截止 → Report → Ambient。完整详情页；支持 Attend、Delegate、Approve、Decline、Archive；委托也必须留下决策主体、执行结果和失败原因。
- **Calendar**：日期/场次/邀请、合同、成员冲突、推进控制；同日多个 Live 各有独立 `live_id`，不可重复结算。
- **Members**：成员 Card/List/Detail、人物关系、粉丝、个人 Cheki 业绩、履历、可知能力范围；面试估计不暴露后台 17 Attr。
- **不显示行业地位**：不提供完整 E−…S Tier 分段、0–10000 Live/Music/Brand/Overall 评分、Top50/行业排名、其他团或本团的行业位置分析；不需要全行业可浏览团体库。其他团只在具体共演、竞争日程和剧情背景中出现。本团成长通过动员、收入、粉丝、歌曲、成员状态、演出机会和章节评价体现。章节评价的 S–E 是**本章目标完成度**，不是偶像行业 Tier。
- **Manage**：Making / Training / Live / Finance 与 R1 Tuning；Audition 只在 Scenario 触发时显示事件工作流，不提供自主发起入口；Policy R2/R3/R4 仅可查看本章/世界设定，不提供常规编辑。成员与歌曲的 Card/List/Detail 读同一实体；不添加固定月会。
- 首页、主视觉、日/中/英语言切换、存档/recovery key、移动端优先的交互继承 v0.9 §1/§19；语言不改变模拟状态。

### 1.2 自动化和玩家干预边界

- **Chronicle Policy 冻结规则**：R4 Group Policy 在整个 Chronicle 中固定，属于世界/团队背景；R2 Operational Rule 和 R3 Operating Model 在每章固定，只有章节脚本可在章节切换时更新；玩家日常只能调整 R1 Routine Tuning。不得沿用父系统“玩家可在开局任意覆写 R2–R4/Decision Boundary”的开放沙盒交互。
- **Team Strategy Meeting / 章节初始化**：训练强度等开局选择仅在剧本明确给定的选项内决定一次，之后 Staff 按已确定方案执行；不能通过普通会议反复修改属于 R2/R3/R4 的 Live/外务/轮换/运营模式。歌曲制作、单场 Setlist、Major Live 和成员个人决定是受剧本限制的一次性 Workflow Decision，不等于 Policy 修改。R1 可按需要微调，不设置固定周期会议。
- 同一套定期公演安排可跨周复用；Staff 自动根据实际疲劳、未成年、缺席、歌曲熟练度与合同进行合法微调。**不能要求玩家每周重选阵容、确认 Cheki 档或重复批准既有定期公演**。
- 仅关键合同、预算超限、无法自动化解决的成员/场地冲突、甄选/Leader/毕业及剧情人事决议为 Blocking。常规 Live 报告和 Weekly Review 默认不阻塞。
- Attend 提供信息、反馈和有限互动机会；Delegate 正常完成运营，不给玩家未到场的虚假目击信息；两者不能绕过真实引擎结算。
- 默认节奏目标：序章快速约 60 分钟、普通约 120 分钟、深度超过 3 小时；这是**试玩验收目标**，非强制时间锁。

- 未成年人当日按学校与生日判定，执行已确定的保守运营时限（未满16岁20:00前结束，16–17岁22:00前结束），不可为满足活动时间强行突破。

## 3. Making、训练与 Live 准备

- **两首原创**各暂定 ¥180,000，走唯一确定的委托→制作→交付→编舞→排练流程，**在 2013-05-24 出道前按固定制作进度完成，不设置随机失败/延期分支**；练习熟练度与实际演出效果可变。制作预算是否含编舞老师须明确费用归属，严禁重复收费。
- 虚构翻唱候选库 12 首，推荐六首（年度报价合计 ¥93,000，TUNABLE），玩家可选择更多或更少；无“必须六首”硬门槛。只有已授权、已编排的曲目可用，未熟练可演出但表现真实受损。
- 首套服装设计 ¥30,000 + ¥25,000 × 正式成员数；训练 Low 2×2h/周、Medium 3×2h/周、High 4×3h/周，排练室 ¥2,500/h；按真实执行扣费，禁止按成员人数重复扣共享排练室租金。
- Song intrinsic Palette、八色 Palette Execution、Key-Part Assignment、Familiarity、成员17 Attr/Traits 与 Performance 按已审核的共用模型实现；Chronicle **不模拟站位/Center/Front/Back 的曝光加成**，只保留关键段落的第一/第二/第三候补与 Staff 自动补位。完整优先级、轮换边界、简化 Impression 公式见 [Key-Part Assignment & Rotation v0.1](Chronicle_Key_Part_Assignment_and_Rotation_v0.1.md)。
- 小/中团正常 Live 默认全员；大团由**本章固定的** Live Policy/Staff 形成出征名单，玩家可在剧本允许的关键活动中干预具体 Lineup，但不能改变章节 R2/R3 轮换规则；不在名单的成员不获该场舞台曝光或 Cheki（**出道场全体正式成员可参加特典会的特殊合同除外**）。

## 4. 活动合同和 Live 经济

| 活动类型 | 门票/出演费 | Cheki | 曝光/结算 |
|---|---|---|---|
| 普通外部售票拼盘 | 本团分到总实收票房15%等分池+25%目当池 | 合同许可且实际出征者可参加 | 真实观看/Impression、票务、特典会分别结算 |
| 2013-05-24 赤坂BLITZ出道 | **本团门票收入0、场租0**（公司安排特殊合同） | **全体正式成员**均可参加出道特典会 | 舞台按真实出演名单；整场千人级为游戏情景假设，不是历史实数 |
| 学校/企业封闭活动 | 按合同固定出演费、实际费用 | 默认禁止 | 仅受邀现场观众；不模拟开放拼盘路人 |
| 2013-09-29 大宮商场公开免费 Live | **本团所有现金收入0**（无票、出演费、收费Cheki/物贩） | 仅免费交流 | 可增加曝光与潜在转化，不能生成现金 |
| 试验/正式定期公演 | 按自主场次真实票务、成本 | **每场都有**，逐成员结算 | 统一 Live Engine，非剧情发钱 |
| 1st One-man / TIF | 各自合同，**不得默认套用普通拼盘分成** | 依合同许可 | 同一 Live Engine、评论与里程碑，无特制结算器 |

**普通拼盘票房**（游戏暂定，不宣称历史业界真实合同）：

```text
R = 整场实际收取的票款
N = 实际参演团体数
m_i = 本团入场目当人数；M = 所有参演团体入场目当总人数
本团门票收入 = R × (0.15 / N + 0.25 × m_i / M)
```

- 余下 60% 不属于参演团体，不在本团账本再次扣除；`m_i` 是购票/入场时登记目当，不是团体粉丝存量或实际观看人数。
- `M=0` 或数据缺失时不得除零、不得擅自将25%等分；需合同回退条款或明确标记该部分未结算。
- **玩家 Live Report 只显示本团最终“门票收入”**，不展示票房池、公式、他团目当和他团收入；内部审计 ledger 可保留各字段。
- 只对**实际完成**的场次结算；无合同的机会不能变成收入。封闭活动目前从经济回归模拟中剔除，不能作为自动现金补贴。

## 5. Fan / Cheki / Finance 的复用接口（不要重写已有模型）

### 5.1 Fan（按 Fan Market v0.2 实现于 Chronicle）

- 持久团队状态：`P=public_count`、`O=otaku_count`；成员级 `A_i=affinity_count`、`W_i=purchase_weight_kjpy`，多推重叠允许 `ΣA_i > O`；`BoxRate=ΣA_i/O` 是派生值。毕业后可有短期 `O_unassigned`，**不得持久存储 Core、C_i、独立 BoxRate**。
- Live Performance + 有效曝光对**P→O、新增成员 affinity**作用较大；特典会交流、可接触性和持续互动对**A_i 留存/形成及 W_i 变化**作用更大。场次记录 momentum，周结算持久 fan state；不可按5/9/15人数另乘获客系数，也不可把 Cheki 一次购买当新增独立 Core。
- 2014-07 左右**`O≈300`** 是将旧“Otaku+Core 300”迁移后的**待重新校准工作目标**，不能将旧 Core 再加到 O 上，亦非剧情硬门槛或历史实测值。团体 O、成员 affinity、购票目当、现场到场、Cheki 买家和销售张数不是同一个量。完整公式/缺口见 Simulation Model Extraction §3。

### 5.2 Cheki（父系统已有逐成员统计）

- **每场、每成员、每价格档**独立统计 `units_1000` / `units_2000`、成交金额、成员分成、其他变动成本、实际使用 slot / 排队及互动反馈；不同档可占用不同服务时间。最终按实际成员和场次汇总团体收入，不允许先猜一个全团 Cheki 总量再按人数分配。
- 默认成员分成 `20% × 该成员该档实收销售额`，其他变动成本按各档配置；团体留存 `Σ units_tier × (price_tier × 0.8 − variable_cost_tier)`。如有非默认成员合同，按实际合同分成替换20%。
- 旧版 **¥490/张** 是“¥1,000、30%分成、假定¥210其他成本”的旧示例；**不得**继续作为默认净留存。若¥210两档均成立（仅敏感性假设），¥1,000档留存¥590、¥2,000档留存¥1,390；¥2,000占30%时平均¥830。真实销售档比和成本需由已有成员级消费/容量模型产出。
- 新增成员通常有**正的长期边际经济贡献**，但不是每人每月保底。边际贡献由她**真实新增**的 Cheki 留存、目当分成和其他收入减去真实增量工资/服装/训练/出征成本；不可重复归因已有团体收入。9人团没有轮换折损；大团按实际选拔出征影响曝光/slot。

### 5.3 Finance

- 初始资金 Easy ¥5m / Normal ¥3m / Hard ¥1.8m；正常现金流由实际合同、逐成员 Cheki、票务、费用产生；无 CD、额外物贩、YouTube 广告收入自动补贴。
- 原有贷款额度/利率、财务三表、歌曲/服装资产 ledger 和成员市场价值非公司资产等规则沿用 v0.9 §18。**现金、营业收入、成本、资产资本化、借款流入分开**，不能把贷款算营业收入，不能将已扣净留存的成员分成/耗材再次记费用。
- 5/9/15 人路线不硬编码利润顺序。旧 v0.6 情景中5人期末现金¥192.5万、9人¥172.6万、15人¥190.1万，是基于全¥1,000档和临时人数乘数的**已过时敏感性结果**；不得用作 Runtime 的 expected snapshot 或回归硬断言。

## 7. 剧情状态机与信息边界

- 事件状态 `DORMANT → ELIGIBLE → OFFERED → RESOLVED/EXPIRED/SUPERSEDED`；`save_id + event_gate + scenario_instance` 幂等；合同已接受不等于演出已完成，必须链接实际 `live_id`。
- 推荐 gates：`G00`创始→`G01`强制面试→`G02`名单/合同→`G03`策略/制作→`G04`原创交付→`G05`5/24出道→`G06`10月小团补员判定→`G07`1–2月试验定期→`G08`3/5正式定期→`G09`莉奈毕业/Leader交接→`G10`One-man→`G11`TIF→`G12`结语/快照。具体旧`Pxx`/旧`Gxx` ID 仅供迁移映射，**不可同时启用两个事件脚本**。
- 角色对话由实际事实账本、性格/关系和玩家选择生成；不伪称有观测证据的具体粉丝转化原因；角色具有独立职业意志，固定毕业不靠惩罚 Attr 实现。
- 章末评级仅 Fans / Performance / Members / Operations + Overall 的 S/A/B/C/D/E **字母等级**，不公开隐藏数值；任何等级可继续第一章，但财务、合同、成员、关系与曲库真实继承。严重资金困难要显式借款/公司支持及成本，不无因果抹账。
- 章间人物和2015–2026剧情基线继承 v0.9 §6/§11 中不冲突的叙事设定；本版不提前重写后续章节。

## 8. Report / Weekly Review / 可观察性

- **Live Report**：JST日期/场馆、可观察到场/动员、**本团最终门票收入**、成员级 Cheki 明细（可展开双档、分成与队列）、实际其他收入/成本、定性现场反应、成员经验。**不展示内部 Performance/Impression 原始数值**，不显示他团票房与目当分账。
- **Member Feedback**：只有成员真实可能观察的感受；不凭空报“X人因为某歌形成 affinity”；不再二次结算粉丝。
- **Weekly Review**：每周一份、由**当期在籍主持人**解读事实和建议，非固定月会；莉奈离队后新 Leader 接班，历史周评保持原作者。普通报告不阻塞连续推进。
- 第一次重要 Live 可分阶段展示（集合/舞台/允许的特典会/结算），之后常规 Live 快速报告；四个里程碑回顾改为**2013-05出道、2014-03正式定期、2014-07 One-man、2014-08 TIF**，2014-01试验定期可作为额外首次教学，不虚构2013-12开幕。
