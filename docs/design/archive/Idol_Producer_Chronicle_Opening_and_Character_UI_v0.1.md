# Idol Producer: Chronicle — 序章开场与统一人物面板 v0.1

## 设计状态
- 起点锁定：2013-01-07，周一，东京。
- 现有角色数据：一期生校准 v0.6，创始三人固定 + 一月十五名候选人；十月使用另一批候选人。
- 基线：Idol GPT Game Design v0.3，Knowledge / Ability Observation；Audition / Scouting；页面为信息空间、会议为决策空间。
- 本文件中的界面示例估计区间皆为演示值，非角色真实能力泄露，实际须经观察算法计算。

## 序章第一天事件链
1. **Monday 2013-01-07 / 09:00（场景时间暂定）**：Inbox blocking `CH-PRO-INTRO-001`，三名创始成员召开新团成立会议。舞台是东京会议室。给出新团愿景选择；不强制玩家修改歌曲/政策数据。
2. **书类选考报告**：Staff 已完成初筛，列出十五位东京籍/东京现居候选人。可见姓名、照片、生日及就学状态、本人介绍、自述演艺经历；能力仅为「尚未验证」及创始三人对申请资料形成的粗略、不确定的倾向。不能把当前 L1/L3 的真实 0–20 值直接展示。
3. **面试计划会议**：玩家可以接受 Staff 推荐的统一面试计划，也可微调同日时段、评审重点、自己是否 Attend。Staff 执行邀请与排程。避免手动点 15 个预约。
4. **统一面试（默认 1 个集中工作日，实际时间为未来日期，由 Staff 推荐）**：15 位依次进行自介/试唱/简短舞步/问答，评审参考莉奈、優花、陽菜三个不同视角。玩家只需处理重点反馈与分歧，不必逐个点击同款确认。实际录取前不显示真实属性。
5. **汇总与录取会议**：卡片/列表切换、排序、加入选拔清单，显示选择人数及人数结构建议。三位面试官可各自提交估计及理由。Producer 决定 offer，Staff 跟进签约；不因选中就立即获得全部真实能力，入团后训练逐渐收窄。
6. **录取后**：Card/List/Detail 复用，入口改为 Members；未录取人的申请档案进 audition archive，不加入成员页。十月新的 15 名候选人，不能简单复用落选人。

## 统一人物视图（共用的 UI model）

### Card：选拔与概览
- 肖像 / 姓名（ふりがな），录取状态，年龄与学校（日历日期驱动）
- 擅长方向文字标签（仅来自观察，如「歌唱可能有潜力」），不展示后端模板字段名
- 五轴 Radar 小图（Singing, Dancing, Visual, Fan Engage, Media Appeal）；用**模糊区间色带**或外包络，不画假精确的折线；未知轴显示问号。
- 评价来源印记：書類 / 莉奈 / 優花 / 陽菜 / 面接 / 個別トレーニング
- 点击打开 Detail；多选在 audition 条件下显式显示「候选」按钮。

### List：比较 / 批量决策
- 列：复选框、姓名、出生年/在校状态、估计定位、综合评价宽泛档、最大不确定维度、到岗状态。
- 可按擅长方向、年龄/学校时段、状态、评审一致度筛选。未观察到的信息不可作为精确排序依据；允许「资料不足」归组。
- 顶部固定入选人数：`3 名创始 + N 名拟录取 = 团队 M 人`，仅提供「建议 9 人」说明，不锁死名额。
- 手机用两行列表，不能依赖宽表横向滚动。电脑可显示五轴区间数字。

### Detail：完整人物页
1. 首屏：肖像、姓名、生日与当前年龄、学校状态及可排班提醒、现状与选拔按钮。
2. Ability：五轴 Radar 区间（可以带缺测）；点击下钻 17 属性时依旧只能显示玩家推定的范围；附最后观察时间与来源，不允许精确后台值出现在前端 payload。
3. Impression：莉奈（整体／育成）、優花（歌与舞台）、陽菜（性格与适应）的原始文字评语、各自可信区间、分歧。评审彼此可不一致，不能把三人估值平均后冒充真实值。
4. Palette：未进团的甄选生八色初始 0，但选拔阶段应显示「未有实际舞台色彩经验／暂无记录」，避免让玩家误解成永久零才能。创始成员 Pink 10 / Red 5 / Yellow 5 的已知经历可展示阶段性熟练度。
5. Career / Trait：仅展示已知证据与公开履历。例如宮原 Model 100 (Junior) 可以看到；所有其他 Trait 隐藏或按记录展示。
6. Calendar：入团后可用时段、学校、考试、法定/运营的最晚工作结束时间。学校档案公开，时间限制随日期计算；在校生排班由 Staff 自动避冲突。
7. Relationships / History：入团前不显示空白关系值或隐藏心理参数；事件发生后逐步出现。
8. Action：Audition=短名单/查看评审/录取；Members=训练报告/参与安排/合同。页面用于查看，重大决定须经 meeting。

## Knowledge state 与呈现
```
character_truth: { attributes_17: integer[17], palette_xp: integer[8], traits: ... }
producer_knowledge: {
  character_id,
  observed_at,
  assessments: [{axis, min, max, confidence, assessor_id, source_event_id, note}],
  known_public_bio: { birthday, school_status, prior_experience }
}
```
- **最初**：书面材料粗区间或 unknown，15 位没有可见真实能力/精确值。
- **面试后**：由观察质量和相关评审专业领域推导区间，来源分别标注；这是主观观察，因此允许偏差，不保证真实值落在每个单个评审区间。
- **后续**：排练、Live、外务、工作人员报告提高精度；不自动把主观范围变成准确值。
- **可信范围与区间宽度**分离。区间非常窄但评审不可靠不应显示成高可信；对 17 属性具体项目可能仍未知。
- **安全边界**：后端评分真实字段不能直接塞给未经许可/尚未观察的前端对象再用 CSS 隐藏。

## 五轴 Radar 设计
- 五轴：Singing / Dancing / Visual / Fan Engage / Media Appeal，与 17 项底层能力保持同一投影公式；投影细则未冻结时，所有样例仅用于视觉示意。
- 每轴显示 `[min,max]` 区域与评审者可见来源；多位评审不同意见可切换为三条半透明估计带。
- 小卡片只渲染宽泛等级/阴影，详情可见区间与文本理由。
- 不展示 Candidate Overall 数值（过早且不可靠），不显示 Palette 伪熟练度。

## 学校与排程约束
- 角色初始全部东京现居，不增加出身地剧情。
- 开场固定 2013-01-07；日本学年 4/1–3/31，4/2 到次年 4/1 作为同届；高三在次年三月毕业。
- 游戏运营规定未满 16 岁 20:00 前结束、16–17 岁 22:00 前结束；不是把 20:00 当成所有日本未满16岁的法定规定。上学日与考试周减少训练余量。
- 面试整体尽量安排在周末白天，运营者/Staff 自动筛查参加者日期年龄与档期。

## 待实现与测试
- 评审模型：三名创始人的专业偏好和评判能力权重；避免全部给出相同意见。
- 共用角色 UI schema + 三布局 + 手机上双行列表 + Detail tabs；可复用于十月补员与日后常规选拔。
- 测试：入团前不泄漏真实属性；同一人物跨布局保持知识一致；面试后仅提升已观察轴精度；九人建议不强制。
- 测试：切换选拔/在籍/历史档案后，根据权限自动显隐动作，不改变原人物 ID。
