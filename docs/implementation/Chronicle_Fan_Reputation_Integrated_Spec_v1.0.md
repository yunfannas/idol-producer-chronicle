# Chronicle｜Fan Lifecycle × Cheki × Reputation 集成规范 v1.0

**状态：2026-10-26 讨论决议／新实施基线（LOCKED 机制，TUNABLE 系数）**。此文件覆盖旧规范中「不允许 Tier/Reputation」「全部新 O 必须立刻分配 A」「外部 X 现场直接转 P」「结束于 2014-08-02」的冲突条款。**未宣称已完成 Runtime 集成或 100-seed 验证**。玩家只展示一项综合 Reputation；内部 Live/Music/Brand 三分项；NPC 仅固定综合数值；不建立世界排行榜。

## 1. Fan state 与周级结算

长期只维护 P、O、每成员 A_i（可重叠）、W_i（跟随成员，表示该成员推し群体平均特典消费倾向）、毕业暂存 U。无 persistent Core、fan IDs、cohorts、Primary。来源归属只在事件内临时保留。

当场真实观看后，可以在 Live 后和**实际完成** Cheki 服务后两次检定成为 O，每位观众单场最多新增一次 O：
- 主动 Team：Team Impression 首次检定；成功只增 O，不要求立即形成 A。
- 主动 Member i：成员 i 的 Live Performance 首次检定；成功增 O 和 A_i。
- 非主动 X：由拼盘观看机会产生（X_idol/X_general），按 Team 现场路径检定；实际成员表演及 Cheki 可给 Member Trigger。X 直接转 O 与进入周 P 曝光池互斥。
- Live 已成为 O 仍可购买 Cheki，但不能再新增 O；未完成服务不触发 Cheki 转化。
- 事件结束后尚未转 O 的**外部新观众**进入**当周 P 曝光池**，不在现场转 P；与 SNS、作品、封闭演出曝光在周日轻量近似去重、扣除已有 P/O 后统一转 P。已有 P 未转 O 不重复生成 P。

主动 Team、Member i 的到场需求单独生成，去重后受门票和容量限制；购票即到场，无额外 no-show。Member 周度吸引系数只乘个人渠道一次：
`Appearance_i=(.8max(Cute,Pretty)+.2min(Cute,Pretty))/20`;
`Appeal_i=.45Appearance_i+.35Fashion_i+.20Performance_i`（后两者归一化）；
`M_i=clamp(1+2(Appeal_i-.65),.5,1.5)`。
Team / Member 来源分别使用 Team Live / 来源成员 Live Performance 决定普通 Cheki 参加意愿。新规赠券仅在授权且合格的实际到场 Public 中、对**原本不打算付费参加**者追加申请机会：Team=30%，Member=50%。领券即提出必用服务请求，不再抽领取或兑换概率；服务仍受成员共享时间容量约束，免费 gross/share=0、有真实变量成本。正常付费新人不会因赠券直接减少预计付费量。

## 2. Cheki 多推消费与拥堵

常态按 A_i、W_i 形成预期消费需求，先对多推重叠与共享消费预算聚合去重。全部队列有余量时直接聚合结算；某成员满时对拥堵队列启用 5 分钟时间片的 FIFO，溢出未服务需求可转向有容量的其他成员。W 不代表个人插队优先级。

相似度 `S_A=min(A_i,A_j)/max(A_i,A_j,eps)`，`S_W=min(W_i,W_j)/max(W_i,W_j,eps)`，`S_ij=sqrt(S_A*S_W)`，初始外溢上界候选 `q_base=.4`。实际转移总需求不得超过 `Overflow_i*q_base*max(S_ij)`，向接收队列按相似度、剩余容量分配，不能重复消费或超出服务秒数。转移只体现为本场临时 `W_j^event=W_j+DeltaD_j/A_j^attend`，**不直接改永久 W**；若有效 A 为零则不作此换算。全满时不再转移，未履约需求流失。永久 A/W 的变化仅由实际满意度及周度 R1 推动。

Retention 周度按 `Loss_O=O*r_O_base*F_retention`，因子由近期 Live 场数、综合满意度、SNS 曝光/活动等连续调整并限幅；A 采用成员满意度对应因子，W 逐渐调整；毕业作为独立事件处理 U 和离团后流失，防双扣。周内曝光去重只需轻量聚合近似，不引入永久个体追踪。

## 3. Reputation & Tier

玩家团体持久保存三项内部评分 Live/Music/Brand，综合目标 `R_target=.45L+.30M+.25B`，显示及获客使用周日平滑后的 `R_current`。NPC 共演团仅 Scenario 固定综合 Reputation。出道前玩家 `R_current=800` 且隐藏；出道 Live 后首次显示已结算值。Brand 初始 **1200（D 下边界）**。Live/Music 在无历史数据时是 unavailable，不是硬填零。

### 3.1 正式统一 Tier 区间（本轮覆盖旧历史表差异）

E− 0–299；E 300–599；E+ 600–799；D− 800–1199；D 1200–1599；D+ 1600–1999；C− 2000–2399；C 2400–2999；C+ 3000–3599；B− 3600–4199；B 4200–4899；B+ 4900–5599；A− 5600–6399；A 6400–7199；A+ 7200–7999；S− 8000–8999；S 9000–10000。历史研究附录中的 E+ 上限 899、D− 下限 900 等旧分界由本表覆盖。

### 3.2 初期保护与正式计算

- 出道前：用于首场拼盘等计算的先验 R=800，UI 不显示。
- 出道 0–6 个月：`R_early=800+DeltaMusicPotential+DeltaSNS`。原创音乐质量、现场接受度与前期有效 SNS 运营成果决定调整，Live 真实票房已入账但暂不进入目标评分。
- 出道 6–12 个月：按照实际日历月龄将 early 与正式分项目标线性插值，保护权重逐渐降至零；Live 对稀疏历史使用样本可信度受限的年化估计，绝不写入财务真账。
- 出道满一年：完全采用正式 `.45L+.30M+.25B`，不要求有 CD/Streaming 才能评价 Music；缺失、不适用于 2013–2014 的流媒体数据不是零销量证据。用于无发行的作品市场代理仍需要原创新曲的实际 Live 接受度/传播证据。
- 每周日 **JST** 结算一次：`R_next=clamp(R_current+clamp(.25*(R_target-R_current),-100,100),0,10000)`；0.25、单周 ±100 是 v1 校准候选。周内全场获客/购票使用上个周日的 R，不现场更新。

### 3.3 LiveScore（正式为过去 12 个月）

主指标实际**可归属于本团的滚动 12 个月等效门票票房**，辅以平均动员和稳定重复性。One-man/自主定期为实际票房；普通拼盘采用合同基础票房分成 + 本团目当折算；Free Live 可按经校准的等效票房，但不记作真实现金收入；封闭外务酬劳不是票房。以历史 L2 连续票房锚插值，不按 Tier 中点硬填。D− 年票房粗参考 ¥1–3M+，但重叠区间不得当硬边界。

**S3-C 现有固定合同期望值示例（截至 2014-08-03 的过去12个月）：**普通拼盘 8×¥16,500=¥132,000；试验定期 4×¥42,000=¥168,000；正式定期 22×¥57,000=¥1,254,000；毕业演出 ¥160,000；首次 One-man 102×¥3,000=¥306,000；合计 **¥2,020,000**，对应 **Live≈1100（D−）** 的校准锚点。此为 Staff 合同容量/固定 sell-through 的预测例子，不是随机种子的实测票房，更不是强制结算得分。One-man 若动员 200 人，则票房 ¥600,000，比默认多 ¥294,000；LiveScore 应连续响应。

### 3.4 MusicScore：两首玩家原创 + 一首系统赠曲

出道前固定制作完成两首玩家原创，于 2013-05-24 首次 Live 公开；第三首系统赠送原创在其**实际公开日**才纳入评分。歌曲来源没有额外加分或折扣。正式发行 CD 与流媒体不存在时，用制作固有质量与已公开歌曲的现场标准化接受度和独立传播估计市场响应，不虚构实体销量。

候选代理：每首 `Q_s=.7Q_production+.3Q_reception`；低样本时 Reception 向 Production 先验收缩；每场标准化 Impression/Expected，按有效听众加权并设单场封顶。已公开曲库奖励第一首 +150、第二首 +100、第三首 +50；`MusicProxy=800+RepertoireBonus(N)+400*(mean(Q_s)-.5)`，无已公开歌曲时使用无样本先验、不得计算空集均值。三首 Q=.55/.60/.50 时 MusicProxy = **1120**，校准目标约 **1100（D−）**。参数为 TUNABLE，不当作市场真实测量；高频反复演出不能无限刷分，翻唱不计原创曲库。

### 3.5 BrandScore：事件 + 运营 + 衰减

Active 月保留系数 **0.995**（月衰减 0.5%），周系数 `0.995^(12/52)`。Non-active / 停团才采用更快衰减（倍率待校准）；某周没有 Live 不自动等于停团。周日 `B_next=clamp(B*d_week+G_SNS+G_release+G_event-penalties,0,10000)`，严禁周衰减与月底衰减双算。

正常 Staff SNS 约 **+6 Brand/月** 的月度等效参考，必须由有效触达/互动/新增 P 支持，不是月月无条件发补贴；初轮 +5～8/月普通、+10～15/月优秀可校准。原创**首次 Live 公开 +5**，后续同曲音源/MV 到累计 +10、实体发行到累计 +15（只补差额、不重复加全额）。正常小型 One-man 首次总共 **+50**，可按官宣 +20、完成 +30（候选拆分），后续普通小型 One-man 不重复；Zepp 及以上按原里程碑表，不叠加小型首次奖。

首次普通 TIF：总 +180，**官宣 70%=+126、实际完成 30%=+54**；官宣最多提前三个月；同一事件两阶段严格幂等。首次 TIF HOT/Main +420（官宣/完成同分期）；TIF 的事件 SNS 曝光可进入周 P 曝光池，与 Brand 行业认证独立；不重复以 Reputation 乘同一笔曝光。其他场馆与 Benchmark 继续参考历史 Brand 事件表，实行完成度/折算票价修正。S3-C Staff 最终 Brand 校准锚 **1450（D）**；非强制结果。

## 4. Reputation 对 Acquisition / 购票的接口

- 拼盘外部观众：**参演团数 n 决定基本观看概率、与全场 NPC 固定 Reputation 的相对差值决定强弱分布**；不模拟出场顺序、晚到与其他团特典会占用。3-man 弱团约 90% 以上，10-man 弱团可约 30%、强团可达约 90%；属于校准锚而非硬保证。所有 X 来自独立观看机会池，不用场馆剩余座位凭空补。
- 单独公开免费 Live：**本团绝对 Reputation × 场地基础曝光**生成当场等效 P；可现场转 O，未转 O 的外部人群入周 P 曝光池，不立刻入 persistent P。
- 普通单独 One-man：已有 P 经 Team/Member 来源分别购票，Reputation 提高 Public 的购买率而不凭空再创造 P；原有 O 依自己的忠诚/票价需求。候选 `M_ticket=(R/800)^3.8`，概率截断并对多周销售去重；已经售出门票不因后续 Reputation 下降回滚。
- 日常官方 Team SNS 等有效曝光候选 `M_reach=(max(R,400)/800)^0.5`，成员路径更弱，指数 **0.25**，Member Appeal 只乘一次；音源传播等也可对名声敏感，但 **每笔曝光最多施加一次 Reputation**。
- TIF 官宣同时令 Brand +126 且带来一次真实事件传播曝光。这两者是不同出口。此前 600–800 左右 Public 的插图示例，额外约 10 人 One-man 购票属于**假设性边际期望**，非 Runtime 已验证默认。

封闭 Live、集团外务（含电视打歌）不做现场 P→O、无 Cheki；按**实际观众数或节目触达 × 已有 Live/单曲 Performance 系数 × 活动曝光折算**进入周 P 曝光池。演出表现照常计算；电视只对当次曲目结算 Impression。普通公开 Taiban、Free Live、One-man 则运行实际观看、Live→O、Cheki→O 的完整链路；剩余新外部观众统一周曝光。

## 5. 周日唯一结算与结局

1. 本周所有 Live/歌曲/工作/队列/财务生成唯一、不可变事实；本周现场 O 转化和 Cheki 已按去重完成事件结算。
2. 汇总新外部观众剩余曝光、SNS、作品、封闭工作曝光，轻量聚合去重，周末结算新增 P；进行 O/A/W 周留存和毕业独立特殊处理。
3. 收集真实门票流水/等效拼盘票房、原创曲实际接受度、SNS 和 Brand 事件；计算滚动 Live、Music 及 Brand 衰减+事件。
4. 依出道月龄计算 Reputation 目标，再**只平滑一次**，生成唯一周日快照。下一周使用新的 R。
5. **TIF 2014-08-02（周六）演出后不立即结束**；正常推进到 **2014-08-03（周日）**，执行所有周末结算、Brand 出演阶段 +54、Reputation 最后平滑、财务与 Fan 汇总后再写结局报告。不额外增加一周、也不强制最终目标等于显示值。

**S3-C 目标复核：** Live 1100 / Music 1100 / Brand 1450 → `R_target=0.45*1100+0.30*1100+0.25*1450=1187.5≈1188`（D−）。锚点用于验证而非保底。Live ¥2.02M、Music 三曲约 1120、Brand 1450 都是待正式 Runtime 审计的条件性数值。
